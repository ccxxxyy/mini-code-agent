# 项目立意与价值定位

回答两个核心质疑：这个项目的立意是什么？市面上有成熟 Agent 为什么还要个人开发？以及后续可做出差异化价值的方向。

## 一、立意：一句话 + 三个支点

### 一句话版本

**这不是"再造一个 Claude Code"，而是把 Agent 的核心机制白盒化**——市面上的 Agent 是能力黑盒，用它不等于理解它。本项目用约 14000 行 Python 把 ReAct 循环、工具系统、上下文压缩、安全防御、多 Agent 编排这些"魔法"全部拆开实现了一遍，每一层都可读、可测、可改。

### 支点 1：学习深度不可替代

用 Claude Code 一年只知道它"能做什么"；亲手实现一个 mini 版才知道"为什么能"。只有实现过才会遇到的认知：

- 工具调用的 JSON 参数是**碎片化流式传输**的（一个 tool_call 被拆成 N 个 chunk），必须按 index 归组增量拼接——不实现根本不知道有这一层
- 上下文压缩不是"删旧消息"：工具调用消息和结果消息必须**配对存在**，删错一条 API 直接 400
- 危险命令拦截黑名单防不住（rm -rf 有无数变体），必须"正则模式 + 用户确认 + 无 UI 默认拒绝"三层
- LLM 会自称 Claude/GPT（训练数据污染），模型身份必须运行时注入 system prompt 才能纠正

这些认知都沉淀在 `docs/tech-notes.md` 的"踩坑记录"里——它们是纯粹使用产品得不到的。

### 支点 2：可控与可定制

商用 Agent 的行为只能"配置"，不能"改造"。本项目每一层都可以直接改代码：

- 想让压缩策略偏向保留代码块？改 `compressor.py` 一个类
- 想给某个目录加只读锁？注册一个 PRE_TOOL Hook，10 行
- 想接入公司内部的私有 LLM 网关？Provider ABC 实现三个方法
- 想审计 Agent 的每一次文件写入？订阅 ToolCallStartEvent 即可

数据主权同理：对话历史、记忆、会话全部存本地 JSON，不经过任何第三方服务器——这对企业内网、涉密环境是硬需求，商用 SaaS Agent 给不了。

### 支点 3：教学与研究价值

95 个文件、876 个测试、零厂商 SDK 依赖（唯一网络库是 httpx，pydantic 仅用于工具参数 schema），是一个**能跑、能测、能读完**的 Agent 参考实现。适合作为：Agent 原理的教学材料、新机制（压缩策略/调度算法）的实验床、"我真正理解 Agent"的证明。

## 二、"市面上有成熟 Agent，为什么还自己造？"

这个问题的隐含前提是"项目目标是替代成熟 Agent"——但实际定位不同。四个回应角度：

### 2.1 类比反问

"有了 MySQL 为什么数据库课要写 mini 数据库？有了 Linux 为什么 OS 课要写内核？"——**造轮子的目的从来不是替代轮子，而是理解轮子**。理解 Agent 内部机制的工程师与只会使用产品的工程师，长期竞争力完全不同。

### 2.2 商用产品做不到的三件事

1. **完全本地化**：对话、记忆、会话全存本地，可接任意私有 LLM 网关——内网/涉密环境的硬需求
2. **任意深度定制**：压缩策略、权限规则、工具行为都是可替换的代码而非配置项
3. **零订阅成本**：按 token 付费给任意兼容 API（DeepSeek 等国产模型成本是 CC 订阅的零头）

### 2.3 它已经不只是玩具

876 个测试、CI 门禁、真实 E2E 验证、七阶段 Spec 开发流程——工程完成度本身就是答卷的一部分。

### 2.4 诚实边界

不回避差距：CC 有更强的模型调优、海量场景打磨、prompt 工程积累。本项目的价值不在"打败 CC"，在**理解 + 可控 + 可扩展**。承认边界反而让立意更可信。

## 三、可做出差异化证据的方向

### 方向 1：与 CC 的对照评测 ✅ 已完成

> 已实现 `benchmarks/` 评测框架，10 个任务 10/10 通过，总成本 $0.0015。CC 结果模板就位待手动补齐。

**做法**：设计 10-20 个标准编程任务（修 bug/加功能/重构/写测试），同一任务分别用本项目和 CC 跑，记录四个指标：

| 指标 | 说明 |
|---|---|
| 任务完成率 | 是否正确完成（人工判定 + 测试通过） |
| Token 消耗 | 每任务总 token（本项目每轮都显示，天然可采集） |
| 成本 | token × 单价（DeepSeek vs Claude 价差 10-50 倍，这是最大优势点） |
| 工具调用次数 | 反映路径效率 |

**预期结论**：完成率 CC 占优（模型强），但**单位成本的完成率**本项目可能反超——"80% 的日常任务用 5% 的成本完成"就是清晰的价值主张。评测脚本本身也是作品（可复用的 Agent benchmark 框架）。

**亮点做法**：把评测做成 `benchmarks/` 目录，结果表格放进 README——用数据说话。

### 方向 2：机制透明度演示 ✅ 已完成

> 已实现 `/trace` 命令：实时展示 ReAct 阶段切换、权限判定（含依据）、工具耗时、LLM token 元信息。193 个测试全过，真实 API E2E 验证。

CC 是黑盒，本项目每个内部状态都可观测。`/trace` 模式现场演示：

- 实时展示 ReAct 每一轮的 THINK/ACT/OBSERVE 阶段切换（EventBus 事件已齐全）
- 展示压缩前后的对话对比（哪些消息被摘要、省了多少 token）
- 展示权限判定路径（这条命令为什么被拦/放行，命中了哪条规则）

**说服力来源**：这是"理解 Agent"的直接证据——你能把内部过程现场展示出来，CC 用户只能描述表面行为。

### 方向 3：垂直场景定制（证明"可改造"的价值） ✅ 已完成

> 已实现三个垂直场景：`/explain` 教学模式（TeachRenderer EventBus 订阅者确定性面板 + Skill 辅助）、`/audit` 合规审计模式（AuditLogger EventBus 订阅者写 JSONL）、offline-ollama 内网离线 Skill（零新代码，复用 OpenAI 兼容 API）。876 个测试全过。

- **内网离线环境**：`skills/offline-ollama/SKILL.md` 提供 Ollama 配置指引 + 推荐模型列表，接本地 Ollama `/v1` 端点全程无外网
- **教学模式**：`/explain on` 开启 TeachRenderer，每次工具调用前确定性打印教学面板（Why this tool / Args / Params guide），不依赖 LLM 遵从——从 Skill 注入方案演进为 EventBus 硬注入
- **合规审计模式**：`/audit on` 开启审计日志，所有工具调用写入 `~/.mini-agent/audit.jsonl`（JSONL 格式，含时间戳/工具名/参数/权限判定）

每个都是"因为拥有源码所以能做"的活证据。

### 方向 4：Agent 机制实验床（研究向）✅ 已完成（前两项）

> 已实现 `experiments/` 实验框架：压缩策略 A/B（none/extractive/llm 三臂 × 5 任务）+ 强弱模型混合编排（三臂 × 2 复合任务）。顺带兑现 roadmap 1.1 的 LLMSummarizeOldest 策略。数据与结论见 `experiments/README.md`。

- **压缩策略 A/B 实验** ✅：提取式摘要 vs LLM 摘要 vs 不压缩，6000 token 小窗口迫使压缩触发，对比"任务成功率 × token 成本"
- **模型协作实验** ✅：Planner 强模型 + SubAgent 弱模型混合编排（AgentTeam 原生支持不同 LLM 注入），三臂对照成本效益
- **死循环诱导实验** ✅：5 场景 × 2 臂实测三重熔断，发现迭代上限是唯一可靠硬熔断，same-tool-6x 在真实 LLM 下从未触发

这类实验产出可以写成技术博客或报告——从"做了个项目"升级为"做了研究"。

### 方向 5：开源与社区（长线）

- 发布 PyPI（`pip install mini-code-agent`），README 英文化
- 定位为 "the readable agent"——市面缺一个测试完备、文档齐全、能一天读完的 Agent 参考实现（对标 tiny-gpt/minGPT 在 LLM 学习中的位置）
- Star 数和使用者反馈本身会成为项目价值的外部背书

## 四、主要思考

**Q: 和 Claude Code 比你的优势是什么？**
A: 不比模型能力，比三样它给不了的：完全本地化（数据主权）、任意深度定制（源码级）、成本自主（接任意便宜模型）。另外它是黑盒我是白盒——我能现场展示 ReAct 每一轮的内部状态。

**Q: 为什么不基于 LangChain/AutoGen 这类框架开发？**
A: 目的就是理解底层。框架把 Agent Loop、工具调度都封装掉了，用框架等于把最有价值的部分外包出去。全项目唯一网络依赖是 httpx，每一行核心逻辑都是自己的。

**Q: 14000 行代码能和商业产品比工程质量吗？**
A: 规模不比，密度可以：876 个测试零网络依赖约 90 秒跑完、CI 双版本门禁、七阶段 Spec 流程、每个设计决策都有文档记录（tech-notes.md）。小而完备优于大而黑盒。

**Q: 这个项目接下来往哪走？**
A: P1-P75 共 75 个阶段已完成（876 个测试），涵盖评测/机制实验/多 Agent 编排/会话自动保存/主题切换/工具并行/双 Esc 中断/长记忆自动化/溢出兜底/TOML 配置/接口冻结（v1.0.0）/覆盖率门禁（81%+）/Diff 预览/文件变更汇总/Windows 终端适配/压缩-重读根治/Anthropic 缓存/流式工具执行/@file 内联/权限规则文件/OS 沙箱/Coordinator 模式/Pydantic Schema 全面增强/远程浏览器模式/Mailbox 跨 Agent 通信。**PyPI 已发布**（`pip install mini-code-agent`），剩余插件生态一个长线项（有意延后——生态建设需要先有用户），定位开源的"可读 Agent 参考实现"。
